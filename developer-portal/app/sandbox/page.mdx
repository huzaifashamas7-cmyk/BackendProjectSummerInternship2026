# Sandbox Environment

The sandbox lets you test API integrations safely, without affecting real production data.

## Creating a sandbox key

Sandbox keys are created through a separate endpoint:

```bash
curl -X POST http://localhost:3000/api/v1/sandbox/keys \
  -H "Content-Type: application/json" \
  -d '{
    "key_name": "My Sandbox Key",
    "scopes": ["exams:read", "exams:write"],
    "user_id": 1
  }'
```

## Using your sandbox key

Use it exactly like a normal API key — the same endpoints, the same authentication method. The only difference is what data you see:

```bash
curl http://localhost:3000/api/v1/exams \
  -H "Authorization: Bearer YOUR_SANDBOX_KEY"
```

This returns sample, pre-seeded data that exists only in the sandbox — completely separate from production.

## Why use sandbox

- Test your integration without creating real exams, enrollments, or results
- Experiment freely — nothing you do here affects real users or real data
- Sandbox and production keys are entirely separate; a sandbox key can never read or modify production data
